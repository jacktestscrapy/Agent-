# Agent设计模式课程内容生成规范

本规范以已完成并审核的前三章为基线，统一后续章节教材正文、图示、代码、案例、审核和仓库维护方式。

## 1. 总体原则
- 保持前三章的教材风格、结构层次和知识深度。
- 讲解体系化、专业、易理解，避免知识点罗列、重复凑篇幅。
- 先生成正文并等待用户审核；未经明确要求，不进入下一阶段。
- 不擅自扩大课程大纲范围，不重写已审核内容。
- 默认不在每章末尾添加练习题。

## 2. 推荐章节组织
按主题适当调整，尽可能包含：背景与问题引入、核心概念、技术原理、执行流程、架构设计、代码实现、应用案例、工程实践与风险控制、总结、延伸阅读（适用时）。不机械套用标题，但讲解必须完整、逻辑清晰。

核心知识点尽可能解释：是什么、为什么、原理、如何运行、如何实现、应用场景及限制。

## 3. 图示
- 核心原理、复杂流程、多组件交互和案例架构应按需要配图。
- 优先使用Mermaid流程图、架构图、时序图、状态图、数据流图或对比图。
- 图示必须有文字解释，并与正文和代码一致。
- 图示不为凑数量而添加，注意清晰、可渲染、避免过度复杂。

## 4. 代码
- 默认使用Python展示Agent核心逻辑。
- 所有Python代码模块及教材中的代码片段必须有解释性注释；核心函数、关键逻辑和复杂流程均应说明。
- 注释解释用途和逻辑，不机械重复代码。
- 代码简洁、直接、便于课堂演示；避免过度封装、无关校验、复杂抽象及无关依赖。
- 代码与教材、图示、案例逻辑一致。
- 模拟实现或简化实现必须明确说明，不得将模拟能力描述为真实能力。
- 代码模块按知识点组织，文件名明确。

## 5. DeepSeek配置
默认采用DeepSeek的OpenAI兼容接口及python-dotenv。统一配置模式：

```python
import os
from dotenv import load_dotenv
from openai import OpenAI

load_dotenv()

client = OpenAI(
    api_key=os.getenv("DEEPSEEK_API_KEY"),
    base_url="https://api.deepseek.com/v1"
)

MODEL = os.getenv("DEEPSEEK_MODEL")
```

- API Key与模型名称从环境变量读取，不硬编码。
- 项目提供.env.example；真实.env不提交，并加入.gitignore。
- 默认每个演示模块可独立初始化客户端；除非教学目标涉及复用或模块化，不强制引入共享客户端模块。

## 6. 案例
案例尽可能真实且贴近企业业务，包含背景、需求、方案、架构、流程、代码、运行说明、结果分析和工程限制（按适用程度组织）。案例必须体现本章核心知识，避免无关功能。

## 7. 章节代码目录与README
默认目录：examples/chapterXX/，按需包含README.md、独立演示模块和项目案例。README至少说明演示内容、目录、环境准备、环境变量、运行命令及模块用途。README须与实际文件和代码一致。

## 8. 仓库结构及命名
教材位于docs/，代码位于examples/chapterXX/，教材文件名遵循章节编号与名称，README.md、requirements.txt及.env.example遵循现有仓库习惯。未经要求不得擅自迁移、删除或改动其他章节及文件。

## 9. 分阶段交付
1. 阶段一：生成完整教材正文，先供用户审核；默认不生成PPT、配套代码或练习题，也不自动同步仓库。
2. 阶段二：根据用户审核意见修改，仅修改要求涉及的范围。
3. 阶段三：审核通过后，生成配套代码、注释、README及必要数据。
4. 阶段四：进行自检；条件允许时进行语法检查或实际测试。
5. 阶段五：用户要求同步时更新GitHub、核验文件内容和提交记录，并准确汇报。

未经用户明确要求，不自动进入下一阶段。

## 10. 检查与禁止事项
- 检查教材结构、讲解完整性、技术准确性、图文一致性、代码注释、环境配置、README、文件结构及测试声明。
- 不默认添加章末练习题。
- 不未经审核生成PPT或配套代码。
- 不未经要求同步GitHub。
- 不擅自重写已审核内容或扩展大纲。
- 不硬编码API Key或模型名称。
- 不生成无解释性注释的代码模块。
- 不声称未经实际测试的代码已成功运行。
- 明确区分静态检查、语法检查、运行测试和真实API测试。
