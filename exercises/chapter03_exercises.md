# 第三章练习：动态 Agent 执行模式

## 练习一：理解 ReAct
1. 阅读 react_agent.py。
2. 为模拟知识库增加 DNS 解析失败和数据库账号权限不足两条知识。
3. 输入不同故障描述，观察 Agent 是否选择合适工具。
4. 记录每轮 Action 和 Observation。

思考：为什么工具执行必须由 Python 完成？连续重复调用同一工具应如何处理？最大轮数过小或过大有什么影响？

## 练习二：扩展 Plan-and-Execute
1. 为任务增加 status 字段。
2. 增加依赖检查，未完成依赖的任务不得执行。
3. 模拟一个任务失败。
4. 设计 Replanner，将失败任务标记为 blocked，并生成替代任务或人工处理建议。

验收：任务 ID 唯一、依赖有效、执行顺序正确、失败状态可追踪。

## 练习三：完善 Reflection
1. 将评价维度拆分为完整性、正确性、可行性和安全性。
2. 要求模型为每个维度给出问题和依据。
3. 评价通过时停止修订。
4. 最多修订两轮。
5. 思考如何用真实单元测试或规则检查替代部分模型自评。

## 练习四：综合案例
背景：FastAPI 服务在 Docker 环境中无法连接 MySQL。

要求：
1. Planner 生成只读排查计划。
2. ReAct 根据模拟配置和知识库动态查询。
3. Reflection 检查结论是否区分事实、推断和待验证事项。
4. 输出包含问题线索、可能原因、验证步骤和风险提示的诊断报告。
5. 禁止自动修改生产配置、重启服务或执行任意 Shell 命令。

## 参考答案要点
- ReAct 的观察结果应进入下一轮上下文；工具必须通过白名单映射执行。
- Plan-and-Execute 应检查任务 ID、依赖和状态。
- Replanner 应明确记录失败、阻塞和替代方案。
- Reflection 应使用明确标准和迭代上限；模型自评不能替代测试。
- Docker 容器内 localhost 通常指向容器自身；是否应改用 MySQL 服务名，仍需核验 Docker 网络、服务定义和实际配置。
