# 第四章练习：工具调用与能力扩展模式

## 练习目标

理解 Tool-Use、Function Calling、Tool Registry 和 MCP 的职责边界；能够为工具定义输入契约、执行白名单校验，并为可能产生副作用的工具设计安全护栏。

## 练习一：扩展工具注册表

阅读 `examples/chapter04/tool_registry.py`，为本地教学知识库增加一个只读工具 `get_service_status(服务名称)`。

要求：

1. 使用本地模拟数据，为“订单服务”和“知识库服务”返回状态说明。
2. 为工具登记用途和参数定义，并拒绝缺少参数、多余参数及错误类型。
3. 增加测试，确认未知服务返回明确结果，未登记的工具不能被调用。
4. 说明为什么不能直接依据模型返回的名称执行任意函数。

验收：只有通过注册表登记且参数符合定义的调用才能执行；所有示例数据均来自本地模拟内容。

## 练习二：完善函数调用往返

阅读 `examples/chapter04/function_calling_agent.py`，使用模拟模型响应完成离线测试，不需要调用真实模型接口。

要求：

1. 模拟模型先后提出工具调用，再返回最终回答。
2. 为单次模型响应增加多个工具调用的处理，并将每个结果关联到正确的调用编号。
3. 验证未知工具、非法 JSON、缺少必填参数和超出最大轮数时的处理结果。
4. 区分参数校验错误与工具运行错误，不要把工具运行失败伪装成成功。

思考：模型返回结构化调用请求后，应用还需要检查哪些信息？哪些错误可以反馈给模型继续处理，哪些情况应停止并交由人工处理？

## 练习三：扩展 MCP 只读能力

阅读 `examples/chapter04/mcp_server.py` 和 `examples/chapter04/mcp_client.py`，为 MCP 服务端增加一个只读工具 `get_service_status(服务名称)`。

要求：

1. 服务端只返回本地模拟的服务状态，不连接真实业务系统。
2. 客户端初始化会话后发现新增工具，并通过 MCP 调用它。
3. 使用中文参数和示例数据；调用失败时输出明确错误。
4. 通过客户端关闭流程验证服务端子进程会被正确清理。

验收：从仓库根目录运行 `python examples/chapter04/mcp_client.py`，完成工具发现和调用；不得使用拼接 Shell 命令的方式启动服务端。

## 练习四：为创建工单工具设计护栏

设计一个“创建工单”工具，但不要连接真实工单系统或执行写入操作。提交工具说明、参数定义和调用流程，并回答：

1. 如何鉴别用户身份、检查其是否有权创建工单，并限制可见工具？
2. 如何校验工单标题、问题描述、优先级和目标系统等必填内容？
3. 如何通过幂等键或去重机制避免超时重试造成重复工单？
4. 哪些情况需要用户确认或人工审批？
5. 审计记录需要包含哪些调用信息？如何避免记录密钥或不必要的敏感内容？

验收：方案明确区分只读查询和写入操作，未经授权或确认时不得执行创建操作。

## 练习五：组合工具调用方案

背景：内部支持人员希望排查“知识库服务不可用”，系统需要查询服务状态、检索本地故障知识，并输出诊断建议。

要求：

1. 绘制 Host、模型、MCP Client、MCP Server 和本地模拟工具之间的交互图。
2. 说明哪些工具通过 MCP 暴露，哪些工具由应用内的 Tool Registry 管理。
3. 描述模型如何通过 Function Calling 提出调用请求，以及应用如何校验参数、执行工具和回传结果。
4. 输出中区分已观察到的事实、可能原因和需要人工验证的事项。
5. 明确说明工具只读、调用轮数有限，并且不会自动修改服务或重启系统。

## 参考答案要点

- Tool Registry 应使用固定白名单和参数定义；输入不合规时不得执行工具。
- Function Calling 是模型提出的调用请求，应用仍需验证工具名称、参数、身份、权限和调用预算。
- 多个工具结果应分别关联对应调用编号；调用轮数耗尽应明确失败。
- MCP 客户端负责协议连接与能力发现，服务端执行自身暴露的工具；MCP 不会自动授予业务权限。
- 创建工单属于写入操作，应增加身份授权、最小权限、人工确认、幂等控制和审计。
- 综合诊断需要区分观察事实、推断和待验证信息；模拟结果不能描述为生产环境实测结果。
